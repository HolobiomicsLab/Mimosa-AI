# Tool discovery & MCP

Mimosa-AI does not ship a fixed catalogue of scientific tools. Instead, it
discovers them at run time through the
[Model Context Protocol (MCP)](https://modelcontextprotocol.io/) — a standard
JSON-RPC interface for exposing tools to LLM agents.

This is the responsibility of [Toolomics](https://github.com/HolobiomicsLab/toolomics),
Mimosa's companion platform. You don't add MCP servers to Mimosa directly:
you add them to Toolomics, start Toolomics, and Mimosa picks them up.

## How discovery works

The [`ToolManager`](https://github.com/HolobiomicsLab/Mimosa-AI/blob/main/sources/core/tools_manager.py)
scans each `AddressMCP` in `Config.discovery_addresses` — by default
`AddressMCP(ip="0.0.0.0", port_min=5000, port_max=5100)`. For every port in
that range it:

1. Attempts an MCP handshake.
2. If successful, fetches the tool list and their schemas.
3. Records the server's URL, tool catalogue, and tags.

The discovered tools become available in two places:

- **Workflow factories** consume them when generating workflow code — each
  agent gets only the tools that match its role.
- **Workflow runners** wire the tools into the sandbox so generated code
  can call them like ordinary Python.

## Anatomy of a workflow's tool block

A generated workflow includes a header block that re-binds the tools it
needs from the local MCP server. The factory emits something like:

```python
# Auto-generated by Mimosa-AI from Toolomics discovery
from smolagents import MCPClient, ToolCollection

tools = ToolCollection.from_mcp(
    server_url="http://localhost:5042",
    tool_names=["fetch_paper", "run_python", "molecular_network"],
)
```

(Exact syntax depends on the workflow prompt version — see
`sources/prompts/workflow_v10.md`.)

## Shared workspace

In addition to tools, Toolomics provides the **shared workspace** at
`Config.workspace_dir`. All generated artefacts — intermediate files,
scripts, downloads, plots — go through this directory. The workspace gives
Mimosa:

- A single filesystem-level rendezvous between agents.
- A predictable path for the verifier to recompute claims against.
- An archive surface for `runs_capsule/` snapshots.

See [Workspace & audit trail](../usage/workspace.md) for how the workspace
flows into the audit trail.

## Adding a new tool

Tools live in Toolomics, not in Mimosa. The general flow:

1. Write your tool as a Python function with type-hinted args + docstring.
2. Register it as an MCP service through Toolomics.
3. Restart Toolomics — it re-exposes the tool on the configured port range.
4. Run Mimosa as usual. The next discovery cycle picks the tool up.

See the [Toolomics docs](https://github.com/HolobiomicsLab/toolomics) for
the exact registration form.

## Tool tagging & filtering

Toolomics tools can be tagged (e.g. `bioinformatics`, `metabolomics`, `ml`).
The factory uses tags to assign relevant tools to specialized agents —
e.g. the workflow's "data wrangler" agent will see file I/O and parsing
tools but not docking simulators.

!!! note "Untagged providers"
    Toolomics may also expose providers without tags. Since
    [commit 0adbbcc](https://github.com/HolobiomicsLab/Mimosa-AI/commit/0adbbcc),
    the precheck explicitly allows untagged providers — they're just made
    available to every agent rather than filtered in.

## Operating without Toolomics

You cannot. Toolomics must be running before Mimosa starts, or discovery
returns an empty catalogue and the synthesized workflows have nothing to
call. Setup typically takes a few minutes — see
[Installation](../getting-started/installation.md) §3.
