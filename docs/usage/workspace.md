# Workspace & audit trail

Every Mimosa run produces a complete audit trail: what was planned, what
was generated, what executed, what was scored, and what the final state
looked like. This page maps out where each artefact lives.

## The three storage locations

```
sources/workflows/<uuid>/    # per-generation: genotype + state + lineage + plots
runs_capsule/<capsule_name>/ # per-run copy of the workspace
sources/memory/              # per-run agent step traces, objective history (cross-run)
```

Plus the Toolomics-managed workspace at `Config.workspace_dir` where
generated workflows actually read and write data.

## Toolomics workspace

`Config.workspace_dir` (set per machine) is the **live working directory**
during execution.
Generated workflows write intermediate files, downloads, scripts, and final
outputs here.

After each generation the workspace is saved to `/tmp/mimosa_run_<session>_<uuid>`
(`WorkspaceManager.save_run_snapshot`). At the end of the run the best run's
snapshot is restored (`WorkspaceManager.restore_best`).

## `sources/workflows/<uuid>/`

One folder per generation. Contains everything needed to understand that
generation in isolation:

| File / dir | Contents |
| ---------- | -------- |
| `workflow_genotype_<uuid>.py` | The Python source of the workflow that was executed. |
| `state_result.json` | Verifier summary and final state. Hybrid fields are under `evaluation.verifier.*`. |
| `evaluation.txt` | Human-readable verifier report (hybrid, legacy and gold verifiers). |
| `textual_gradient.txt` | The gradient sidecar fed to the next mutation (hybrid, legacy and gold verifiers). |
| `evolution_prompt_<uuid>.md` | Exact prompt sent to the LLM to produce this workflow. |
| `lineage_<uuid>.json` | Parent UUIDs + operator (`seed`/`mutation`/`crossover`). |
| `reward_progress.png` | Score across iterations, written at the end of the run. |
| `evolution_tree.png` | Rendered lineage tree, written at the end of the run. |

The hybrid verifier keeps per-task registries (`hybrid_registry_<key>.json`:
claim ladder, cached scorer scripts, format digests, per-generation score
vectors) under the verifier temp directory (`_verifier_tmp`, or the configured
`temp_dir`). The default `policy_bt` verifier keeps its per-task tournament
state under `<workflow_dir>/.policy_bt/`.

The best run is selected at termination, and its snapshot becomes the run's
final state.

## `runs_capsule/<capsule_name>/`

The workspace contents are copied into a capsule folder for long-term storage
(`LocalTransfer.transfer_workspace_files_to_capsule`), then the workspace is cleaned:

```
runs_capsule/<capsule_name>/
├── <copied workspace files>
└── evaluation_results.json   # written by the capsule evaluator
```

Capsules are intended for:

- Sharing a complete reproduction.
- Comparing two runs of the same task.
- Submitting a complete reproduction to a grader.

`<capsule_name>` is generated by the `capsule_namer_model` LLM from the goal
(`LocalTransfer.create_capsule_name`). A deterministic fallback is used when
the LLM returns nothing. A task token is appended when one is given.

## `sources/memory/`

Cross-run state that doesn't belong to a single generation:

- **Per-run step traces** — one JSON file per agent under `sources/memory/<uuid>/`. `--memory_cli` reads them.
- **Objective history** (`objective_history.json`) — stored under `sources/memory/` in a source checkout.

## What the hybrid verifier consumes

When the hybrid verifier scores a generation, it reads:

1. **The task goal** — the source of every claim in the ladder.
2. **Workspace snapshot** — the files the policy scorers measure
   (scripts, logs, deliverable artifacts).
3. **The per-task registry** — previous generations' score vectors, for
   the pairwise reward and the variance filter.

It writes back **only** to the evaluation fields in the response — not to
the workspace. The mutator sees the `abstracted_textual_gradient`, not
the raw scorer output.

## Resetting between benchmarks

For unbiased benchmark evaluation, run

```bash
./cleanup.sh              # top-level generation folders + tmp/
./cleanup.sh run_1        # or: empty one named subfolder (asks first; -y skips)
./cleanup.sh -n run_1    # dry run: list what would be deleted
```

before kickoff, on the folder your `workflow_dir` points at, so cached
workflows from previous runs don't contaminate similarity-based parent
selection (`WorkflowSelector` only reads the top level of `workflow_dir`).
The default deletes only top-level generation folders of
`sources/workflows/` (`YYYYMMDD_HHMMSS_<id>`, `single_agent_*`,
`generation_failed*`) and empties `tmp/`; named campaign subfolders
(`run_1`, …), their `.policy_bt/` tournaments and the top-level logs are
kept. It never touches `runs_capsule/`, `sources/memory/` or `run_notes/`.

!!! warning "Don't delete by hand"
    `cleanup.sh` knows which directories are runtime state vs. source.
    Wiping `sources/` indiscriminately removes things like
    `sources/prompts/` and `sources/modules/` that you actually need.
