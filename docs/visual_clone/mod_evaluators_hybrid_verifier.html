hybrid_verifier — default verifier package

Ten Python files turn one task goal into 8–12 stage-tagged claims, write a deterministic scorer per claim, and score each generation with a pairwise win-rate. The reward drives the verification flow; the package sits under the wider evaluators area. Two classes build HybridVerifierEvaluator: WorkflowEvaluator (default channel) and, in gold mode, GoldFeedbackEvaluator as an inner verifier.

PAIRWISE_MODES = ("temporal", "temporal_strict", "mean_diff", "sign_sum", "escalation"); DEFAULT_PAIRWISE_MODE = "temporal"; STAGES is the default ladder and FIGURE_STAGES (visual first) the figure-task ladder, passed in as stages. Reward formula: (wins + 0.5 * ties) / n_pairs; with no previous generation the reward is the mean claim score and fallback is "mean_claim". Bradley–Terry reward is sigmoid(beta_now) after centering, with an L2 ridge of 1.0 and Newton iterations capped at 100.

The stage ladder

StageRankWhat the claim gradesWhen it decides a pair
visual0*Figure deliverable judged against frozen goal-anchored visual claims (figure tasks only)First stage checked on figure tasks
script0Delivered code exists, reads the goal inputs, implements the methodFirst stage checked; pass-count decides
log1Run logs: loss trend, accuracy at a step, NaN or crash markersChecked only when the script stage ties
result2Prediction CSV columns match the input, row counts, value sanityChecked last; stage mean-diff breaks the tie

Stage names live in claims.py (STAGES, and FIGURE_STAGES with visual first); the same tuples are copied in aggregation.py. A claim passes its rung at score >= PASS_THRESHOLD = 0.5. * On figure tasks the ladder is FIGURE_STAGES (visual first), so every rank after visual shifts by one.

how the ladder decides, per pairwise mode
ModeDecision rule
temporalEarliest differing stage wins by pass-count, then by stage mean-diff
temporal_strictFirst differing claim in temporal order wins outright
sign_sumFlat: more claims scored higher wins
mean_diffFlat: larger total score difference wins
escalationFlat: sign-sum first, mean-diff as tie-break

Unmeasured claims (score=None) are skipped in every mode. aggregation.claim_stats drops a claim with no observed score (all_fail) or with zero variance over >= 2 observations (zero_variance); layers.ClaimsEvidenceLayer.revise then asks for up to refinement_rounds replacement claims, bounded by MAX_CLAIMS_TOTAL = 14.

The visual stage reads the figure deliverables with the vision model. The script stage reads the candidate's own code. The log stage regex-parses log files. The result stage reads the artifacts.

Covered by tests/hybrid_verifier_test.py: test_static_violations_catches_write_and_network_apis.

Amber: scorer scripts are LLM-written code that runs as plain host subprocesses (sys.executable, cwd = the scored workspace), not inside the SmolAgents AST sandbox, so the static screen above is the only guard.

Amber: evaluator.py::HybridVerifierEvaluator.__init__ reads getattr(config, "temp_dir", None), but Config defines runner_temp_dir and has no temp_dir, so the per-task registry lands in workflow_dir/_verifier_tmp. Exception: in gold mode gold_feedback/evaluator.py::gold_hybrid_config passes a config copy whose temp_dir is that path plus _gold, so the inner hybrid keeps a separate registry.

Why it matters: the same cached scorer script grades every generation of a task, so a reward difference means an artifact difference, not a measurement difference.
