Package vetting and run transparency

Two small folders do Mimosa's paperwork. sources/security/check_package.py checks installed package versions before a run, and sources/transparency/ turns a finished run's memory into ASTRA YAML, a recipe.py, and a decision list. This page maps both, and marks the one place where the docs disagree with the code.

File card - decision_extractor.py

sources/transparency/decision_extractor.py

Asks the judge model once per compacted step; each reply is null or one decision JSON. Failures and malformed replies are counted, not hidden.

420 lines · classes: Decision, Option, ExtractionResult · prompt: prompts/decision_extraction.md

signatures and constants
extract_decisions(steps, goal, memory_path, llm_config=None, max_workers=6) -> ExtractionResult
_extract_one(step, goal, template, memory_path, llm_config) -> Decision | None | sentinel
_parse_response(raw, source_step) -> Decision | None | _MALFORMED
_validate(payload, source_step) -> Decision | None
_merge_options(existing, later) -> Decision
_MAX_WORKERS = 6        _ID_PATTERN = ^[a-z][a-z0-9_]*\Z

Three outcomes stay distinct: None (the model said null), _MALFORMED (prose, truncated JSON, schema violation), _EXTRACT_FAILED (the LLM call raised). Counts land in astra.yaml under extraction. An unresolvable chosen_option_id is never guessed unless the reply listed exactly one option.

Steps are extracted concurrently (max 6 workers) but merged in trace order, so the first occurrence wins for label, rationale and chosen option; later alternatives are unioned by id.
