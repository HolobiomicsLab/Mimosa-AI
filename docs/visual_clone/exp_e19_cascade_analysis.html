e19_cascade_analysis — cascade and ensemble retest

This follow-up asks whether sending tied E19 pairs through a second channel adds within-task signal. It makes zero LLM calls and reads only the E19 ledgers plus the E15, uniform and reward scores already stored in the E19 json. It appends one section to the E19 files of record; no separate results file exists.

Design — primary ranker first, secondary on ties

Diagram 3 — 11 boxes. load_state (L51) rebuilds the 9 contrast groups and the pair records; pf_e19 (L126) and pf_e19_v2 (L138) read the pair sign, pf_from_scorer (L109) reads the persisted E15 and uniform scores, pf_reward (L118) reads the recorded reward. cascade() (L142) falls through to the secondary channel when the primary ties or is undefined. The dashed bus carries those pair outcomes into the three readouts; each readout writes rows into one section.
