e5_embed — the MiniLM claim-embedding cache

E5's embedding rung needed one vector per distinct claim name before any fitting could start. This page covers e5_embed.py, the script that precomputes that cache into one .npz file. The cache is then read by e5_run.py L56, e5b_splits.py L47, e9_deployment.py L84 and e13_common.py L36.

The script

experiments_verifiers/harness/e5_embed.py

Precomputes MiniLM embeddings for every distinct claim name and for name plus description, then stores both matrices and the name list in one .npz file.

exs = C.load_examples()                                     # L18
eval_paths = C.load_eval_paths()                            # L19
descs = C.parse_descriptions(exs, eval_paths)               # L20
names = sorted({c["name"] for e in exs for c in e["claims"]})   # L22
texts_nd = [f"{n}. {descs.get(n, {}).get('description', '')}".strip() for n in names]  # L23
model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")   # L28
emb_n = model.encode(names, batch_size=128, show_progress_bar=True, normalize_embeddings=True)     # L29
emb_nd = model.encode(texts_nd, batch_size=128, show_progress_bar=True, normalize_embeddings=True) # L30
np.savez_compressed(out, name_emb=emb_n, name_desc_emb=emb_nd,
                    names=np.array(names), has_desc=np.array([n in descs for n in names]))   # L33-L34
print("wrote", out, emb_n.shape, emb_nd.shape)              # L35

Both calls pass show_progress_bar=True and normalize_embeddings=True (L29, L30), so rows are unit vectors.

Red: the module docstring (L4) says the cache holds names, descs, but the write call (L33–34) stores names and a boolean has_desc. No descs member exists in the file, and no consumer reads has_desc (grep for has_desc over e5_run.py, e5b_splits.py, e9_deployment.py, e13_common.py: 0 uses).

Amber: the script re-encodes both text variants in full on every run; it never checks for an existing cache, so a re-run spends GPU or CPU time again.

Why it matters: two versions of the same text are cached, name only and name plus description. The rung built on the description version wins the ladder, which is what makes this cache the E5 input that mattered.
