workflow_selection.py

WorkflowSelector finds stored workflows under config.workflow_dir and picks the parents for the next generation. One path samples the live SelectionPressure archive; the other is a cold-start disk scan filtered by goal similarity and by score. Similarity uses MiniLM embeddings when they load, and a word-overlap fallback when they do not.

Main diagram - discovery, then the two parent paths

Diagram 1 - two stages. Discovery (top row) scans the folder and embeds goal text; parent selection (bottom row) either samples the archive or ranks the disk candidates. Every box names a real method with its line range. Group page: mod_core_selection.html.

The similarity model is loaded on the first similarity call, not at startup: the comment at lines 52-55 says an eager download crashes the app where the model host is unreachable, and the HF_ENDPOINT mirror is suggested there.
