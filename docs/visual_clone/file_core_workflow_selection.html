workflow_selection.py

WorkflowSelector finds stored workflows under config.workflow_dir and picks the parents for the next generation. One path samples the live SelectionPressure archive; the other is a cold-start disk scan filtered by goal similarity and by score. Since the gold-feedback change (ca72107), the disk scan also drops generations graded by the gold (oracle) verifier, unless this run is itself a gold run.

Main diagram - discovery, then the two parent paths

Diagram 1 - 10 boxes, two stages. Discovery (top row) scans the folder and embeds goal text; parent selection (bottom row) either samples the archive or ranks the disk candidates. Every box names a real method with its line range. Group page: mod_core_selection.html.

This file does not pick the shipped capsule. The capsule argmax is evolution_engine.py::_select_best_run (line 136), which drops fallback rewards via _run_reward_is_fallback (line 72) and FALLBACK_REWARD_KINDS; the oracle skip here only guards the parent pool and the planner reuse lookup.

The similarity model is loaded on the first similarity call, not at startup: the comment at lines 52-55 says an eager download crashes the app where the model host is unreachable, and the HF_ENDPOINT mirror is suggested there.

Control logic - which folders become candidates

Diagram 4 - 9 boxes, the filter chain inside discover_workflows (sources/core/workflow_selection.py:85-141). Each "no" or skip branch drops the folder. The oracle test runs after the state check and before the code read, so it can use the parsed state_result.

oracle - leaks gold A gold run (verifier_kind == "gold") keeps oracle folders; every other run skips them and logs [LEAK GUARD]. tests/gold_feedback_test.py:1000 checks both cases.
