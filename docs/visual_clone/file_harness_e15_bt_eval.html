e15_bt_eval.py

The offline evaluator of the E15 preference pilot: it fits one Bradley-Terry model per group from the judgment ledger, writes a label-free preference gradient for every generation, and only then reads the SR labels to compute pairs-correct, an M2 replay and diagnostics. It makes no LLM calls and rewrites no evidence. It writes one results JSON, one Markdown report and 148 gradient text files.

The file enforces its own label order in prose: the docstring says SR labels are read only in the evaluation stage (line 7) and the protocol block records the same rule as gold_hygiene (line 531). The call order in main matches that claim: gradients first (line 381), SR readouts after.

The gradient files quote judge reasons and add the theme token list, which is derived from lost and tied verdicts (lines 216–217). Those files are written before any SR label is touched, so they are safe to feed to a mutator; this page does not verify that any other tool consumed them.

The Markdown verdict sentence is chosen by thresholds on numbers that only exist after the run (lines 642–657). It is a report rule, not part of the metric.
