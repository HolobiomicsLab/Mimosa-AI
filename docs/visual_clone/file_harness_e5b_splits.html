e5b_splits.py

This script stress-tests the E5 rung L3 (score-weighted MiniLM name+desc vectors into a logistic regression) across many random 80/20 splits, to see whether E5's leave-one-task-out 0.753 was a lucky fold. It runs three split units: example-level (leaky), task-level (honest) and campaign-level holdout. It writes one JSON and one Markdown file per run; run it with uv run python experiments_verifiers/harness/e5b_splits.py (L12).

Diagram 1 — what the file does, left to right

Diagram 1 — 9 boxes. Cyan = work inside e5b_splits.py, dashed grey = file outside it. Solid = call, dashed = read/write. main (L154) calls example_split (L69) or group_split (L76) per seed, then fit_eval (L90), then summarize (L127) and paired_stats (L135) for each of the three blocks (L187, L190). It also calls e5_run.make_f_l3 (L299) and e5_run.loto_eval (L302–303) for the LOTO anchor, writes the JSON itself (L354) and calls write_md (L356). select_C_inner (L101) is only reached from the ablation (L281) and the inner-CV block (L320).

Diagram 2 — data in and data out

Diagram 2 — 6 boxes. main returns the out dict (L357) and is the only writer of the JSON (L354); the Markdown comes from write_md(out) (L356, write at L433). There is no config file and no shared state object: every input is a module constant (L35–39), a frozen data file, or the embedding cache.

Diagram 3 — the seed loop and the C-selection loop

Diagram 3 — 6 boxes. Two loops. The outer loop walks the seeds: fit_eval (L90) returns nan when the train side (L92) or the test side (L96) holds one class, and main then drops that seed (L180, L200, L237). The inner loop lives in select_C_inner (L101): five C values from C_GRID (L38), four task folds, single-class folds skipped (L115), best mean AUC wins (L122), and C stays at C_FIXED = 0.1 (L39) when no C improves.
