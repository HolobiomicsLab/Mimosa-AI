policy_bt_verifier — the default verifier channel

Eleven Python files run the default verifier (config.py:102): one generation is snapshotted, gated on a reproduction contract, optionally re-executed in a fresh venv, understood by an LLM reconnaissance, compared with every predecessor by one cached policy in a restricted subprocess, and rated by a regularized Bradley–Terry fit. This page follows one generation end to end; every quote is from the working tree at 84db677+wt and cites file and line.

Notes and gotchas

Amber: a generation that fails reproduction is a real 0.0 with an actionable gradient, but a verifier-side fault (unreadable LLM answer, unsafe output path, venv failure, policy worker crash after repair rounds) returns reward: None with skipped_reason="verifier_instrument_error" — the engine skips it, it is never a scientific loss.

Why it matters: the reward is relative to the tournament so far — overall_score = 1.0 means "beats every predecessor seen so far", not "good in absolute terms".

standing rules of the current implementation
  • Criteria are frozen by the first eligible generation; later generations only add or repair schema adapters, so success cannot drift with observed performance (policy.py:1062–1070, 1140–1196).
  • Both orders and self-ties are mandatory; a mirrored disagreement or a non-tie self comparison is a policy fault, repaired and retried up to policy_bt_repair_rounds, never a coin flip (policy.py:892–929).
  • Evidence must be real: adapter values need paths the reader actually observed, and verdict evidence must copy adapter output (policy.py:754–790, 792–827).
  • Reproduction logs land inside the snapshot (.policy_bt_reexec/) so adapters can read them (reexec.py:68, 400–415).
  • Gold firewall: recon, policy and verdict prompts never see benchmark gold files or hidden answers (prompts.py:5–9).
