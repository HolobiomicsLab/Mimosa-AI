e9_deployment.py

This script replays deployment on the sane data written by e8_blast_radius.py: it trains the learned claim-importance scorers L3 and L3b on the other campaigns, scores the asb_full_iterative_1 generations, ships the top-scoring generation per task and checks its recorded SR. It compares that against the recorded-reward policy P0, three claims baselines, and within-campaign leave-one-task-out. It writes one JSON and one Markdown file; run it with uv run python experiments_verifiers/harness/e9_deployment.py (L17).

Diagram 1 — what the file does, left to right

Diagram 1 — 10 boxes. Cyan = work inside e9_deployment.py, dashed grey = a read path or a written file. Solid = call, dashed = read/write. main (L201) calls load_sane L203, manifest_index L204, load_emb L205, then fit_score from the two scorer loops (L251, L263), then replay three times (L284, L307), then its own diagnostics, then writes the JSON at L448 and calls write_md at L450. The two boxes labelled “in main” are the scorer dictionary and the diagnostic counts; they have no function of their own.

Diagram 2 — data in and data out

Diagram 2 — 7 boxes. Three read files, four module constants, one returned dict (L452) and two written files. e5_common is imported at L33 for _auc, uniform_score, v0_reward and standard_metrics (used at L274–276, L343). No config field and no environment variable is read.

Diagram 3 — the per-task ranking rule and its tie-break

Diagram 3 — 7 boxes. The ranking rule is two sorts in a row: first by order_key = latest uuid_long (L168, defined L279), then by score (L169), so ties ship the latest generation. fit_score returns zeros when its train side holds one class (L147–148) and select_C_inner skips single-class folds (L130). The inclusive sensitivity (L293–312) adds the recovered rows but only reaches the reward baseline and the oracle, because recovered rows carry no claims.
