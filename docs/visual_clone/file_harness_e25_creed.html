e25_creed.py

This file is the E25 "CREED" harness: phase 1 autopsies the frozen E18 pairwise-comparator run by depth-classifying its 599 comparison scripts, and phase 2 retrials the comparator with four pre-registered depth-contract variants. It runs by hand, one subcommand at a time, from the command line. The judge model is fixed to openrouter/deepseek/deepseek-v4.1-flash L102 with reasoning disabled L225, under a $6 hard cap for all of E25 L104.

Diagram 1 — the job: autopsy the frozen E18 comparator, then retry it with a depth contract

Diagram 1 — the order of work. main L2020 dispatches eight subcommands L2022 to cmd_* functions L2032–L2034. Phase 1 loads the frozen E18 records (load_e18_judgments L142), classifies every script by decision depth (classify_decision L334) and writes the autopsy files. Phase 2 builds one merged prompt per pair (gen_messages L944), asks for one comparison script, runs it in a subprocess sandbox and appends one judgment row per (pair, variant, phase). The depth classifier is a shared helper: cmd_autopsy calls it L484, and phase 2 calls it again in label_free_proxies L1266 and cmd_eval L1736. The two exception classes are small: StopRun L123 (cost cap) and CallFailed L127 (LLM call).

Diagram 2 — data flow: frozen E18 artifacts in, E25 files out

Diagram 2 — config fields read: none; every knob is a module constant L104–L112 (HARD_CAP_USD 6.0 L104, MAX_CODE_ATTEMPTS 3 L105, MAX_LLM_AMBIGUOUS 150 L106, SUBPROC_TIMEOUT 90 L107, E25_SEED 20260925 L108, N_BOOT 10000 L109, PREVIEW_CAP 2048 L110, DIGEST_FILES 2 L111, SLICE_BYTES 1200 L112). Returned values are in-process values, not files: the autopsy out dict L681, the per-pair rec L1164 or L1176, the retrial out dict L1765, the report strings L1828 and L1943, and main returns None L2034. argv is read by cmd_pilot L1252, cmd_arena L1353, cmd_swap L1373 and cmd_eval L1606.

Diagram 3 — logic: the three-attempt repair ladder of one pair

Diagram 3 — the branching inside run_pair_variant L1117. At most MAX_CODE_ATTEMPTS 3 code attempts L105: attempt 1 asks for a new script L1120, later attempts send a repair prompt L1122. A failed call breaks the loop L1130–L1131. A missing fenced block L1134 or a static violation L1140 continues the loop with feedback L1136 and L1142. Only a script whose stdout parses L1146 and whose metrics are not all null L1150 becomes outcome: script L1164; otherwise the pair ends as outcome: error L1176. Inside _call_llm the same shape repeats: six tries L215, a cost-cap check before each call L217, doubled max_tokens on a truncated answer L246–L247, and a sleep of min(45, 2**attempt*3) seconds L258. StopRun L123 is never swallowed: run_queue re-raises it L1208–L1209, while other pair failures are counted as errors L1210–L1212. The STOP flag L120 is tested in the three loops of cmd_autopsy_llm L1462, L1480 and L1524.
