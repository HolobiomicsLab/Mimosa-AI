e19c_online_bt.py

Replays the production Bradley–Terry reward over the frozen E19c arena, one fit per generation in evolution order, with zero LLM calls. It appends an online_bt_view section to the E19c ratchet result files. It runs as a one-shot script: python experiments_verifiers/harness/e19c_online_bt.py.

Diagram 1 — what the script does, left to right

Diagram 1 — 8 boxes. Order of work: read the frozen arena, index the 19 groups, sort the surviving claims, fit one Bradley–Terry reward per generation in evolution order, then measure that arm (pairs-correct, paired Δ, M2 replay, flips) and append both result files. main() L51 is the only top-level function that runs; pairfn L42 is a factory used by three metrics.

Diagram 2 — data in, data out

Diagram 2 — 8 boxes. Dashed arrows are file reads and writes; the solid arrows are in-memory values. LABEL_FREE L37, OUT_JSON L38 and OUT_MD L39 resolve under experiments_verifiers/results/ because EV L25 is the package root. No Config field is read: the file imports no config module.

Diagram 3 — decision and loop rules

Diagram 3 — the real branches. Three rules decide the numbers: the None guard in pairfn L45–47 (a missing score drops the pair), the contrast filter L81 (9 of 19 groups carry the SR contrast), and the tie rule L47/L99 (exact ties count 0.5 in pairs-correct, and the recorded contrast tie rate is 0.0068). The M2 pick uses argmax_ship with the latest-uuid tie-break from the helper. There is no early stop, no retry and no skip test: re-running overwrites the JSON key but appends the Markdown section again.

Boundary of this page: it describes one file. The arena data, the ratio of contrast to non-contrast groups, and the meaning of sr belong to the experiment page and e19c_ratchet.py.
