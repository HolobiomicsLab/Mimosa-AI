digest.py

This file takes deterministic head/middle/tail samples of a workspace's deliverable files and asks one judge call for a short format digest per file. It runs once per task, from ClaimsEvidenceLayer._ensure_digests (layers.py), and the result is cached so every later scorer prompt sees real column names and log grammar. The hybrid_verifier page places it in the pre-policy stage.

Diagram 1 — the file's job: rank files, slice bytes, one judge call, parse digests

Diagram 1 — 9 boxes. The pipeline runs inside ensure_digests (lines 116-175); it calls sample_sections (157), digest_prompt (165), then parse_digests (170). render_digests is not called from ensure_digests: the caller calls it (layers.py:302, 315, 327). The judge HTTP call sits behind the llm_text callable, so this file makes no network call.

Diagram 2 — data flow: files read, values returned, nothing written

Diagram 2 — 6 boxes. The only config field is hybrid_verifier_digest_max_files (config.py:88, default 8); it is read by the evaluator (evaluator.py:208) and passed to the layer as max_files. This file writes nothing: the caller stores the returned map in the registry JSON.

Diagram 3 — control logic: four bail-out guards

Diagram 3 — 8 boxes. The digest step is optional by design: line 166 carries the comment # noqa: BLE001 - digest is an accelerator, not a dependency, so a failed call logs a warning and the scorer prompt falls back to the union inventory alone.
