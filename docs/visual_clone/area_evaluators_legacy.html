Legacy claim verifier

The legacy claim verifier scored a workflow by extracting atomic claims and checking each claim with a generated Python script; it is deprecated since 2026-09-24 and replaced by the hybrid temporal-ladder verifier. Its five modules now live in the deprecated sources/evaluators/legacy_verifier/ sub-package. This page maps the pipeline in one diagram, and maps the other evaluators under sources/evaluators/ in a second diagram.

Diagram 1 - what the legacy verifier did

Diagram 1 - the legacy pipeline, read left to right then snake back; the five boxes are the modules of sources/evaluators/legacy_verifier/. Symbols: legacy_verifier/verifier.py::VerifierEvaluator.evaluate runs it, legacy_verifier/verifier_claims.py::_VerifierClaimExtractionMixin._extract_claims and ::_declare_claim_importance build the rubric, legacy_verifier/verifier_per_claim.py::_VerifierPerClaimMixin._generate_specs_parallel writes the scripts, ::_run_verifier_with_recovery runs them, legacy_verifier/verifier.py::VerifierEvaluator._aggregate scores with _HARD_FAIL_CAP = 0.89. The cap fires when a claim of importance ≥ 8 (_HARD_FAIL_IMPORTANCE) fails.

Diagram 2 - the other evaluators and their interface

Diagram 2 - evaluator.py::WorkflowEvaluator.evaluate reads evaluator_type and calls one channel; evolution_engine.py:810 passes evaluator_type="verifier" only. Every evaluator extends base.py::BaseEvaluator, which loads WorkflowInfo, calls the judge LLM and writes evaluation.<type> into state_result.json; ScenarioEvaluator reads rubric JSON through ScenarioLoader.load_scenario (see area_benchmark_evaluation.html) and grounding.py calls perspicacite_client.query_perspicacite.
