e19_bt_eval.py

Turns the E19 claim-score ledgers into pair decisions, a Bradley-Terry table and the labels-side readouts (pairs-correct, M2 replay, independence, claim categories). It reads SR and reward only in this stage and writes no LLM prompt. Run with uv run python experiments_verifiers/harness/e19_bt_eval.py.

Diagram 1 — what the file does

Diagram 1 — 8 boxes, one per stage in execution order. main (L239) drives every box. Labels (SR, reward) enter at b5 only; the gradient transcripts at b6 hold measured scores and no labels. All numbers in the graphs come from functions in e15_bt_eval.py (pairs_correct, cluster_boot, paired_boot_diff, argmax_ship, bt_fit_weighted).

Diagram 2 — data in and out

Diagram 2 — 9 boxes. Solid = call, dashed = read/write. The two deliverable files are rewritten whole (write_text at L676 and L869); the gradient directory holds one file per generation and is created with mkdir(parents=True, exist_ok=True) at L156. The pilot and duel records are read only when they exist (L551, L557, L560).

Diagram 3 — 9 boxes, one per real rule.
