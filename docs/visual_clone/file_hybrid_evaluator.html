evaluator.py

This file holds HybridVerifierEvaluator, the class the rest of Mimosa calls to score one generation: it loads the workflow, runs the evidence layers, filters claims, takes the pairwise reward, and writes the verifier artifacts. Its one public entry is evaluate(uuid), called by the evaluator facade after each generation. The wider loop is on flow_verification.html and mod_evaluators_hybrid_verifier.html.

Diagram 1 — the file's job: one generation in, scores and artifacts out

Diagram 1 — 10 boxes. HybridVerifierEvaluator extends BaseEvaluator and is built in __init__ (lines 133-218), which hands the claims layer two callbacks (llm_text at 197, run_script at 198). layers.ClaimsEvidenceLayer.collect calls those callbacks, then evaluate takes the loop back at line 326.

Diagram 2 — 8 boxes. Note the temp root: line 192 reads getattr(config, "temp_dir", None), and config.py defines runner_temp_dir (line 236), not temp_dir (grep over config.py, 2026-10-02), so the per-task registry always lands under workflow_dir/_verifier_tmp in this working tree.

Diagram 3 — control logic: the guard tree around evaluate

Diagram 3 — 9 boxes. The short-circuit path exists for parity with the legacy verifier: it writes a non-empty gradient so the engine never receives an empty one (module docstring lines 6-9). Tests test_short_circuit_rewards_zero_with_synthetic_claim (line 780) and test_short_circuit_flags_artifacts_when_workspace_has_them (line 804) cover both branches.
