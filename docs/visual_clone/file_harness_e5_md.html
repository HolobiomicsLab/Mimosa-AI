e5_md.py

This 140-line script renders the markdown summary of an E5 run from its results JSON: it picks the JSON file, reads it, and appends one section after another into a line buffer that becomes the .md file. It runs by hand, uv run python experiments_verifiers/harness/e5_md.py [results_json] (docstring L3); no other Python file imports it. Every number it prints is copied from the JSON, not recomputed (L27).

Diagram 1 — 10 boxes. The script is module-level code plus one function: fmt (L19) is the only def in the file. Section groups are shown together because they all follow the same pattern — read a key of d, format it, append lines.

Diagram 2 — data in, data out

Diagram 2 — one read, one write, one printed line. The script reads no config field and takes no state key: every path is derived from __file__ (EV L11) or from the argument at L12.

Diagram 3 — the four decisions the renderer makes

Diagram 3 — the renderer never recomputes a statistic; it formats stored values. The one hard failure mode is a missing top-level key, which raises KeyError; only the gate block is read with a fallback (L70).

Amber: the fallback source is sorted(glob(...))[-1] (L12), a name-order maximum, so a hand-typed date earlier than the newest file still wins only when passed as an argument. The run date on L27 is copied from the JSON, not from the file name.
