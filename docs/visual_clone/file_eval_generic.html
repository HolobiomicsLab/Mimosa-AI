generic.py

GenericEvaluator scores one workflow run with four independent LLM judges: goal alignment, agent collaboration, output quality and answer plausibility. It averages the four scores, can subtract a numerical-fraud penalty, and writes evaluation.txt plus the evaluation.generic block of state_result.json. The module header marks it [DEPRECATED](V1); the default verifier channel is the hybrid package.

Main diagram - four judges, one averaged score

Diagram 1 - one pass over a finished run: build the execution text, fetch optional literature grounding, run four single-criterion judge calls, parse each score, average, then write the two artefacts. Line numbers are from sources/evaluators/generic.py; solid arrows are direct calls, dashed arrows are value or file movement.

Each criterion is judged in a fresh LLMProvider context, and the file says why: "to avoid inter-criteria bias" (line 65).

Data flow - what goes in, what comes out

Diagram 2 - inputs, in-memory state and outputs. The four judge calls are cached on disk under memory_dir/<uuid>/; the grades leave through evaluation.txt and the evaluation.generic block of state_result.json.

Control logic - per-criterion failure, penalty clamp, save fallback

Diagram 3 - three branch groups: per-criterion failure handling (sources/evaluators/generic.py:368-404), the optional penalty with its clamp and its 0.0 fallback (:419-441), and the two save steps with their local error handling (:443-472).

Amber: the comment at line 411 says the overall score is "excluding answer_plausibility", but the key list immediately below (line 412) includes answer_plausibility, so all four criteria are averaged.
