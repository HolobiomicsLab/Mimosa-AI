e3_run.py

This is the E3 runner: one command-line stage at a time, it scores frozen workspaces with a cross-family judge ensemble, corrupts copies for a sabotage control, and computes the metrics JSON. The markdown summary for the pilot run lives in e3_md.py, not here. Every judge call is cached on disk, so a stage can be re-run and resumes where it stopped L74–L75.

Diagram 1 — main L424 is a dispatcher: one stage name selects one function. build_frames L39 is always called first L429, so every stage works on the same 102-row frame.

Diagram 2 — data flow: frozen rows in, state plus one results JSON out

Diagram 2 — config fields read: none; load_dotenv L425 fills os.environ from the repo env file. The state file is the resume point: a stage skips every uuid already in state["instances"] L75.

Diagram 3 — logic: dispatch, the corruption cycle, the frame rule

Diagram 3 — the mode is picked by position in the pick list L169, so ten picks cover the five modes twice. Three fallbacks replace a mode that has nothing to corrupt. The frame rule L52–L60 forces one SR-false row into every task that would otherwise have no contrast pair.
