workflow_factory.py

This file asks an LLM for a LangGraph workflow body, checks its shape, and splices it with the state schema, the SmolAgent factory and the MCP client code into one runnable script. It is the multi-agent path, called by WorkflowOrchestrator._generate_workflow_code; single_agent_factory.py is its one-agent twin. It writes the script and its metadata; the runner executes them later.

Diagram 1 — the job: templates plus one LLM body, validated and spliced

Diagram 1 - 11 boxes. The chain is: read config, load MCP tools, make the two folders, read the two templates, ask the LLM for the body, save it, validate its shape, splice and compile, return. Solid arrows are the real calls inside craft_workflow.

Diagram 2 — data flow: templates in, one script and four files out

Diagram 2 - the factory reads three files and several config fields, and returns text. The two write boxes are split on purpose: one happens in this file, the other happens only when the generated script runs.

Diagram 3 — logic: the cache rule and the validation ladder

Diagram 3 - left: the cache rule, decided by one string comparison. Middle and right: the four required patterns, then three more checks, then two compile() calls. Each failure raises ValueError; the last one prefixes the UUID.
