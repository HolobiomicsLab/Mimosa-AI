gradient.py

This file writes the two texts of one generation: the textual gradient the mutator reads, and the human-readable evaluation.txt. It runs at the end of HybridVerifierEvaluator.evaluate, after the reward is known, and it only formats measured facts in flight: uncommitted changes. The package view is on mod_evaluators_hybrid_verifier.html and the wider flow on flow_verification.html.

Diagram 1 — the file's job: measured maps in, two texts out

Diagram 1 — 11 boxes. build_gradient calls _sign per claim (218) and _persistent_failure_rows once (208); both public functions return a plain str. Section 1b (L296) lists claims that stayed below PASS_THRESHOLD = 0.5 in this generation and in every scored predecessor: they have no decisive loss, so section 1 never shows them. The header runs from Task goal: (287) straight to Bottom line: (289).

Diagram 2 — data flow: keys read and texts returned

Diagram 2 — 6 boxes. Every value here is measured scorer output or a counter built in evaluate; the module docstring states the intent as "Faithful transcript of measured facts; no editorializing, no labels" (lines 13-14). prev_scores is the raw score dict of each previous registry generation (evaluator.py:557), so it is not filtered by registry.py::_SCORER_CRASH_EVIDENCE.

Diagram 3 — control logic: which claim lands in which section

Diagram 3 — 10 boxes. Sections 1, 1b and 2 use the same sort key (stage rank, then temporal_index, lines 117-118 and 203-204), so each reads script before log before result. Section 1b has no row cap, unlike sections 1 and 2 (5 rows each). test_gradient_v5_decisive_first_no_elimination_point (tests/hybrid_verifier_test.py:853) checks the section order, the goal-anchored rows and the stage headers of the report.
