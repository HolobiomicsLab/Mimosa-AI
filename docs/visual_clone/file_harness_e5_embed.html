e5_embed.py

This 35-line script precomputes the MiniLM embeddings that the E5 ladder and its follow-up experiments read from disk. It takes the distinct claim names of the frozen claims file, encodes each name and each name. description string with all-MiniLM-L6-v2, and writes one compressed .npz cache. It runs once, by hand: uv run python experiments_verifiers/harness/e5_embed.py (docstring L3); no other Python file imports it.

Control flow: none to draw

This file has no function, no class, no if statement, no loop and no retry. It is one straight-line pass: load (L18–L20), list names (L22), build texts (L23), encode twice (L29–L30), save (L33–L34), print (L35). The only conditional expression is the dictionary fallback descs.get(n, {}).get('description', '') at L23, which defaults to an empty description when a name has none.

So there is no decision diagram on this page. The rule that would otherwise be drawn — "no description → encode the bare name" — lives in the caller's data, not in a branch of this file.
