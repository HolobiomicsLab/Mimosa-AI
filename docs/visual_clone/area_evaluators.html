Evaluators

sources/evaluators/ holds the judge channel that scores every generation of a workflow. WorkflowEvaluator.evaluate routes a run to one backend: the hybrid verifier by default, the deprecated per-claim verifier on request. The generic and scenario evaluators are reachable only by a direct library call, not from the CLI.

Which evaluator runs when

Diagram 1 - sources/evaluators/evaluator.py selects the backend. Dashed boxes are deprecated.

The legacy per-claim verifier is still reachable, not dead code. WorkflowEvaluator.__init__ reads config.verifier_kind, and when the value is legacy it imports VerifierEvaluator lazily from sources/evaluators/verifier.py (evaluator.py::WorkflowEvaluator.__init__, lines 85-98). Set the field in the config file or pass --verifier_kind legacy (main.py:77-80, config.py:459); the default is hybrid (config.py:76).

selector code, verbatim
verifier_kind = str(getattr(config, "verifier_kind", "hybrid")).lower() if verifier_kind == "legacy": # Escape hatch: the deprecated multi-source verifier. # Imported lazily so the default path never loads it. from .verifier import VerifierEvaluator self.verifier_evaluator = VerifierEvaluator(config, workspace_dir=verifier_workspace_dir) else: self.verifier_evaluator = HybridVerifierEvaluator(config, workspace_dir=verifier_workspace_dir) self.verifier_kind = verifier_kind

Path: sources/evaluators/evaluator.py lines 85-98. The choice is made once, in __init__, so a running engine cannot switch channel mid-run.

Call site, verbatim (sources/core/evolution_engine.py lines 808-812): self.judge.evaluate(uuid=uuid, agent_answers=agent_answers, evaluator_type="verifier", scenario_rubric=scenario_rubric). This is the only call site of WorkflowEvaluator.evaluate in the repo.

WorkflowEvaluator.__init__ also builds GenericEvaluator and ScenarioEvaluator on every construction, even when the run uses the verifier channel (evaluator.py:77-84). A scenario rubric passed with --scenario reaches verifier_evaluator.evaluate, whose signature is evaluate(uuid) only, so the rubric does not enter verifier scoring.

The Evaluator interface and its implementers

Diagram 2 - base.py::BaseEvaluator and its four subclasses. Dotted arrows are imports or mixin use.

Every backend writes the same artifact: evaluation.txt in sources/workflows/<uuid>/ (generic.py:445, scenario.py:182, verifier.py:945, hybrid_verifier/gradient.py:229), so the report on disk is written by whichever backend ran that generation. Only one backend runs per generation.

BaseEvaluator.__init__ reads memory_dir, workflow_dir, model_pricing, reasoning_effort and judge_model, and fails with EvaluatorError when one is missing. GenericEvaluator.evaluate returns None; it writes scores into state_result.json under evaluation.generic.

Error classes live in base.py: EvaluatorError, WorkflowDataError, ScenarioError, LLMEvaluationError, ScoreExtractionError. extract_json_payload is reused by hybrid_verifier/digest.py:23 and hybrid_verifier/layers.py:22.
