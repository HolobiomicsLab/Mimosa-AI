Evaluators

sources/evaluators/ holds four top-level modules (evaluator.py, base.py, grounding.py, __init__.py) and five sub-packages that hold the backends (hybrid_verifier/, gold_feedback/, generic/, scenario/, legacy_verifier/). config.verifier_kind picks the verifier channel: hybrid (default), legacy (deprecated) or gold (oracle control that reads the benchmark gold and wraps the hybrid verifier). The generic and scenario evaluators are reachable only by a direct library call, not from the CLI.

Which evaluator runs when

Diagram 1 - sources/evaluators/evaluator.py selects the backend. Dashed boxes are deprecated. The ORACLE box builds its own inner HybridVerifierEvaluator (gold_feedback/evaluator.py::GoldFeedbackEvaluator.__init__). oracle - leaks gold

The legacy per-claim verifier is still reachable, not dead code. WorkflowEvaluator.__init__ reads config.verifier_kind once: legacy imports VerifierEvaluator lazily from sources/evaluators/legacy_verifier/verifier.py, gold imports GoldFeedbackEvaluator lazily from sources/evaluators/gold_feedback/, and any other value builds the hybrid verifier (evaluator.py::WorkflowEvaluator.__init__, lines 88-110). Set the field in the config file or pass --verifier_kind hybrid|legacy|gold (main.py:76-83, JSON load at config.py:516); the default is hybrid (config.py:106). HybridVerifierEvaluator is imported at module level (evaluator.py:21) and listed in __all__; the legacy and gold names are not re-exported there.

Amber: gold reads the benchmark grader's verdict against the gold reference and feeds it back into evolution oracle - leaks gold. It needs a task row that only --science_agent_bench sets (csv_mode.py::CsvEvaluationMode._set_gold_feedback_task); main.py::warn_gold_feedback_mode prints the leak warning at start-up.

Imported lazily so the # default path never loads it. from .gold_feedback import GoldFeedbackEvaluator self.verifier_evaluator = GoldFeedbackEvaluator( config, workspace_dir=verifier_workspace_dir ) else: self.verifier_evaluator = HybridVerifierEvaluator( config, workspace_dir=verifier_workspace_dir ) self.verifier_kind = verifier_kind

Path: sources/evaluators/evaluator.py lines 88-110. The choice is made once, in __init__, so a running engine cannot switch channel mid-run. An unknown value such as "nonsense" falls back to the hybrid verifier (tests/gold_feedback_test.py::test_facade_unknown_kind_still_falls_back_to_hybrid).

Call site (sources/core/evolution_engine.py, EvolutionEngine._evaluate_workflow_phenotype, lines 921-938): when self.judge.verifier_kind == "gold" the engine calls await asyncio.to_thread(self.judge.evaluate, ...), because benchmark grading takes minutes; every other kind keeps the direct call self.judge.evaluate(uuid=uuid, agent_answers=agent_answers, evaluator_type="verifier", scenario_rubric=scenario_rubric). These two branches are the only call sites of WorkflowEvaluator.evaluate in sources/.

WorkflowEvaluator.__init__ also builds GenericEvaluator and ScenarioEvaluator on every construction, even when the run uses the verifier channel (evaluator.py:80-87). A scenario rubric passed with --scenario reaches verifier_evaluator.evaluate, whose signature is evaluate(uuid) only, so the rubric does not enter verifier scoring.

The Evaluator interface and its implementers

Diagram 2 - base.py::BaseEvaluator, its four subclasses and the four sub-packages that hold them; each implementer box names its package. grounding.py (left, below sources/core) is a module-level import of generic/generic.py (line 29) and legacy_verifier/verifier.py (line 41); its edge is left out to avoid a crossing. Dotted arrows are imports or mixin use. GoldFeedbackEvaluator (bottom right) is not a subclass: it duck-types evaluate(uuid) -> dict, sets _save_results = BaseEvaluator._save_results, and imports WorkflowInfo and is_oracle_generation from sources/core/workflow_info.py; the grey box at bottom left is outside this area.

Every backend writes the same artifact: evaluation.txt in sources/workflows/<uuid>/ (generic/generic.py:445, scenario/scenario.py:181, legacy_verifier/verifier.py:945, hybrid_verifier/evaluator.py:778-780), so the report on disk is written by whichever backend ran that generation. In gold mode the inner hybrid writes it first, then gold_feedback/evaluator.py::GoldFeedbackEvaluator._persist prepends a leak banner and rewrites textual_gradient.txt with the grader feedback.

BaseEvaluator.__init__ reads memory_dir, workflow_dir, model_pricing, reasoning_effort and judge_model, and fails with EvaluatorError when one is missing. GenericEvaluator.evaluate returns None; it writes scores into state_result.json under evaluation.generic.

Error classes live in base.py: EvaluatorError, WorkflowDataError, ScenarioError, LLMEvaluationError, ScoreExtractionError. extract_json_payload is reused by hybrid_verifier/digest.py:23 and hybrid_verifier/layers.py:30.
