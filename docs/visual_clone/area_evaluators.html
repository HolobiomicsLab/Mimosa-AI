Evaluators

sources/evaluators/ holds four top-level modules (evaluator.py, base.py, grounding.py, __init__.py) and four sub-packages that hold the backends (hybrid_verifier/, generic/, scenario/, legacy_verifier/). WorkflowEvaluator.evaluate routes a run to one backend: the hybrid verifier by default, the deprecated per-claim verifier when config.verifier_kind = "legacy". The generic and scenario evaluators are reachable only by a direct library call, not from the CLI.

Which evaluator runs when

Diagram 1 - sources/evaluators/evaluator.py selects the backend. Dashed boxes are deprecated.

The legacy per-claim verifier is still reachable, not dead code. WorkflowEvaluator.__init__ reads config.verifier_kind, and when the value is legacy it imports VerifierEvaluator lazily from sources/evaluators/legacy_verifier/verifier.py (evaluator.py::WorkflowEvaluator.__init__, lines 85-98). Set the field in the config file or pass --verifier_kind legacy (main.py:76-81, config.py:470); the default is hybrid (config.py:76). HybridVerifierEvaluator is imported at module level (evaluator.py:21) and listed in __all__; the legacy name is no longer re-exported there.

selector code, verbatim
verifier_kind = str(getattr(config, "verifier_kind", "hybrid")).lower() if verifier_kind == "legacy": # Escape hatch: the deprecated multi-source verifier. # Imported lazily so the default path never loads it. from .legacy_verifier import VerifierEvaluator self.verifier_evaluator = VerifierEvaluator(config, workspace_dir=verifier_workspace_dir) else: self.verifier_evaluator = HybridVerifierEvaluator(config, workspace_dir=verifier_workspace_dir) self.verifier_kind = verifier_kind

Path: sources/evaluators/evaluator.py lines 85-98. The choice is made once, in __init__, so a running engine cannot switch channel mid-run.

Call site, verbatim (sources/core/evolution_engine.py lines 808-812): self.judge.evaluate(uuid=uuid, agent_answers=agent_answers, evaluator_type="verifier", scenario_rubric=scenario_rubric). This is the only call site of WorkflowEvaluator.evaluate in the repo.

WorkflowEvaluator.__init__ also builds GenericEvaluator and ScenarioEvaluator on every construction, even when the run uses the verifier channel (evaluator.py:77-84). A scenario rubric passed with --scenario reaches verifier_evaluator.evaluate, whose signature is evaluate(uuid) only, so the rubric does not enter verifier scoring.

The Evaluator interface and its implementers

Diagram 2 - base.py::BaseEvaluator, its four subclasses and the four sub-packages that hold them; each implementer box names its package. grounding.py (left, below sources/core) is a module-level import of generic/generic.py (line 29) and legacy_verifier/verifier.py (line 41); its edge is left out to avoid a crossing. Dotted arrows are imports or mixin use.

Every backend writes the same artifact: evaluation.txt in sources/workflows/<uuid>/ (generic/generic.py:445, scenario/scenario.py:181, legacy_verifier/verifier.py:945, hybrid_verifier/evaluator.py:778-780), so the report on disk is written by whichever backend ran that generation. Only one backend runs per generation.

BaseEvaluator.__init__ reads memory_dir, workflow_dir, model_pricing, reasoning_effort and judge_model, and fails with EvaluatorError when one is missing. GenericEvaluator.evaluate returns None; it writes scores into state_result.json under evaluation.generic.

Error classes live in base.py: EvaluatorError, WorkflowDataError, ScenarioError, LLMEvaluationError, ScoreExtractionError. extract_json_payload is reused by hybrid_verifier/digest.py:23 and hybrid_verifier/layers.py:30.
