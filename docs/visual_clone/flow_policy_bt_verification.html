Policy-BT verification flow

One generation enters the policy-BT verifier as a copy of its workspace. The verifier checks the reproduction contract, re-runs the script in a disposable venv, plans one comparison policy, and compares the generation against every predecessor. Reward and gradient come from a regularized Bradley–Terry fit over all pair verdicts.

Diagram 1 - one PolicyBTVerifierEvaluator.evaluate(uuid) call (sources/evaluators/policy_bt_verifier/evaluator.py), rows top to bottom. The left rail names the stage tag that row logs through evaluator.py::_log; rows marked in mute grey log no stage (the rerun, the bundle handoff, the vision result and the publish). VISION_UNAVAILABLE fires only when the vision channel errors; ERROR closes the run on any instrument failure. The tags are free strings - no STAGES constant exists in the package.

The verifier grades an owned copy, never the workflow workspace: artifacts.py::snapshot copies the evidence, and reexec.py requires the caller to pass that copy. Re-execution is trusted local shell execution, not an OS sandbox - TRUST_BOUNDARY = "trusted_local_shell; venv and clean environment are not an OS sandbox" (reexec.py:66).

Which channel decides this pair

Diagram 2 - how one pair gets its verdict (evaluator.py::PolicyBTVerifierEvaluator._compare_pair → _artifact_verdict). Pairs where either side failed the reproduction contract are decided by the execution gate with channel "execution"; everything else uses the one cached policy, with the vision model only as a tie-break on relevant images.

a, b = left["execution"], right["execution"] winner = "tie" if a["eligible"] == b["eligible"] else "a" if a["eligible"] else "b"
— sources/evaluators/policy_bt_verifier/evaluator.py::_execution_verdict (verbatim)

Pair verdicts are cached on (a, b, policy_version) inside the committed tournament (evaluator.py::_compare_tournament): a stable bundle re-uses every earlier decision, and a version change (new adapter, new policy, new criteria) invalidates them. An ineligible generation still takes part in the tournament - its pair verdicts come from the execution gate - but it never receives adapters, and tournament.py::fit_ratings pins its rating to 0.0.

A cache hit on the bundle still re-plans adapters for generations that lack an assignment, and every new adapter is smoked against its own snapshot before the tournament (policy.py::PolicyEngine._prepare_smoke): snapshot vs itself must tie. The venv is never cached: each re-execution provisions a fresh virtual environment (reexec.py::_execute).

Verifier-side faults - an unreadable contract answer, a hallucinated script selection, an unsafe output path, a venv that cannot be created, or a policy that still fails after all repair rounds - raise through evaluate() and become skipped_reason = "verifier_instrument_error" with reward None: the generation is left out of the QD archive, never scored 0 (evaluator.py::_record_instrument_error; reexec.py::ReproductionInstrumentError).
