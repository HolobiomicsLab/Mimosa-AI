Batch running and grading

This page maps the batch running and grading area: the CSV-driven task loop, the execution sandbox, and the ScienceAgentBench graders. It shows where generated code runs, what isolates it, and which metrics come back. Read it before touching csv_mode.py or the graders.

Diagram 1 - batch pipeline

Diagram 1 - step symbols: CsvEvaluationMode._generate_task_science_agent_bench builds the prompt, ExecutionSandbox.run_generated_code and ExecutionSandbox.run_eval_script run the two subprocesses; sources/benchmark_evaluation/csv_mode.py::CsvEvaluationMode._process_single_task_once holds this order. Concurrent mode (run_concurrent_eval_loop) runs the same steps under an asyncio.Semaphore.

Diagram 2 - the dashed line is a process boundary, not a security boundary. sources/benchmark_evaluation/execution_sandbox.py::ExecutionSandbox._subprocess_env copies the host environment for the child.

sources/benchmark_evaluation/execution_sandbox.py

Builds one shared Python 3.10 venv, then runs the generated script and the grader in temp copies.

1 126 lines · classes: ExecutionSandbox, EvalInfraError · venv key: hash of base packages + constraints

signatures, pins and isolation facts
ExecutionSandbox.run_generated_code(script_path, script_name, expected_output, timeout=3600) -> (bool, str)

SANDBOX_PYTHON_VERSION = "3.10", resolved from $MIMOSA_SANDBOX_PYTHON then python3.10 on PATH; a version mismatch raises. PINNED_CONSTRAINTS caps numpy<2.0, pandas<=1.5.3, torch<=2.3.0, rdkit<=2023.09.5 and others.

What it isolates: the dependency set (own venv), the working directory (capsule copied to /tmp/mimosa_sandbox_*/execution or /eval), the GPU (CUDA_VISIBLE_DEVICES="") and the process group (SIGKILL on timeout). What it does not isolate: the host environment (os.environ.copy()), the network, and the filesystem outside the temp directory.

Caller timeouts: CapsuleEvaluator passes 900 s for VER and 300 s for the grader.

Rules: VER runs the generated script; if VER is false, SR is set false without running the grader. If SR is true, CBS is set to 1.0 without computing it. An EvalInfraError sets status: "excluded" and VER/SR/CBS to None.

evaluation_results.json keys: task_id, timestamp, status, VER, VER_message, SR, SR_message, CBS, cost_usd, summary, plus infra_error or CBS_error when present.

sources/benchmark_evaluation/codebert_scorer.py

Scores generated code against the gold code with CodeBERT token embeddings.

167 lines · functions: calculate_codebert_score, preload_codebert_model · model: microsoft/codebert-base

signatures and the scoring rule
calculate_codebert_score(generated_code_path, gold_code_path) -> float
preload_codebert_model() -> tuple | None

Rule: tokenize both files to max_length = 512, drop padding with the attention mask, L2-normalize, take the best cosine match per token in both directions, then report the F1 of precision and recall. The tokenizer and model load once per process behind a lock.

It raises on failure; CapsuleEvaluator.calculate_codebert_score owns the 0.0 fallback and records the reason in CBS_error.

what each ablation row records
CsvEvaluationMode._evaluate_snapshot_ablations ->
  {evolution_index, uuid, VER, VER_message, SR, SR_message,

Source of the rows: /tmp/mimosa_run_<session_id>_<uuid>, one folder per evolution iteration, written by sources/utils/workspace_management.py::WorkspaceManager.save_run_snapshot. _sort_key orders folders by evolution_index, with orphan uuids last.

Precedence rules for reading a graded run

Quoted from AGENTS.md, section "Auditing finished runs", evidence map:

`ablations` outranks the verifier reward — it is what the benchmark actually graded. `source` is `snapshot` (genotype re-graded) or `capsule` (final submission). `ver_success` / `sr_success` / `total_eval` semantics are undocumented: quote them, don't interpret them.
The capsule defines the task result, not the last generation folder. Read the prediction artifacts' headers/first rows; they ground every claim about what was delivered.
Artifact presence ≠ run success: errored rounds (`on_error: true`) can still leave complete outputs.
A round with `on_error: true` has no `evaluation.txt` and no gradient — the run-time error cause is not recorded anywhere; say so instead of guessing.

Order matters: read ablations[] first, then the capsule evaluation_results.json, then the per-round folders.
