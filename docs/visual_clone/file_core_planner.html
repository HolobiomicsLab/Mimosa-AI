planner.py

Layer 0 of the task run flow: it turns one goal string into a multi-step Plan, then runs each step through the evolution engine. It runs only in --goal mode (main.py:241) and in benchmark CSV mode, never in the --task path. Entry point is Planner.start_planner (L925).

Mismatch, my reading only: _extract_json_from_code_block (L295) accepts a block only after a line starting with ```json (L313), and returns None when it finds no such fence (L325). Four tests in tests/planner_json_extraction_test.py expect more: test_extract_plain_fence, test_extract_raw_json_without_fences, test_extract_prose_wrapped_json and test_extract_skips_broken_block_for_parseable_span (L162–L181). Following the code text, those four would fail. Not verified by a run.

Amber, dead code and docstring drift: _verify_required_inputs (L625) has no caller anywhere in the repo; DependencyError (L51) is never raised; _verify_expected_outputs documents a produced_outputs parameter (L649) that its signature (L644) does not have; the cache-reuse branch elif self._get_evolve_success(best_match) is commented out at L759, so any cached match with .is_success is returned without the score check.

Why it matters: make_scientific_grounded_prompt prints the first 2048 characters of the retrieved literature straight to stdout (L152) on every attempt, so the grounding text lands in run logs and console output, not only in the prompt. The same call is made in benchmark CSV mode, where it costs one Perspicacite round trip per plan.
