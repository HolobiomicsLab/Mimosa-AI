bs_detection.py

BullshitDetectorNumerical walks the agent memories of one run, collects numeric literal values, and asks an LLM judge to score each value 0-10 for fabricated origin. generate_short_fraud_report and propose_penalty_score turn the high-risk values into one penalty in 0.0-1.0, which generic.py subtracted from the overall score. The module header marks it [DEPRECATED] and "prototype module, now unused"; the only importer is sources/evaluators/generic.py.

Main diagram - memory in, fraud scores out

Diagram 1 - the whole pipeline of the file: memory files become per-role entries, numbers are extracted with filters, backtraced into a timeline, formatted into judge prompts, scored per value, then summarised into reports and one penalty. Line numbers are from sources/evaluators/bs_detection.py.

Two values are returned per run: the analysis bundle from analyze_all_agents_numerical (lines 576-582) and the penalty dict from propose_penalty_score (line 786). The penalty is what generic.py subtracts.

Data flow - what goes in, what comes out

Diagram 2 - inputs, in-memory state and the two kinds of output. The judge call is the only network step; the module keeps no cache of it because analyse_backtrace builds its LLMProvider without a memory_path (sources/evaluators/bs_detection.py:466-470).

Control logic - number filters and penalty fallbacks

Diagram 3 - the three decision groups: the extraction filters (sources/evaluators/bs_detection.py:257-293), the strict threshold test of the short report (:671), and the penalty fallbacks plus clamp (:730-786).
