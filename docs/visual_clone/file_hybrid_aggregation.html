aggregation.py

This 445-line file is the scoring core of the hybrid verifier: it turns per-claim scores into one reward. It holds the zero-variance drop filter, the pairwise comparison modes and the two reward functions (win-rate and Bradley–Terry). It runs on each generation, called by evaluator.py L514 and L526, and it reads no config key and touches no file.

Diagram 1 — what the file does: filter dead claims, decide each pair, average into a reward

Diagram 1 — the whole file. aggregation.py::win_rate_reward L207 and aggregation.py::bradley_terry_reward L313 both accept the same three inputs (now, previous, claims) plus mode; the caller picks one through the config key hybrid_verifier_reward (read at evaluator.py L216).

Diagram 2 — data flow: vectors and a mode in, a reward dict out, nothing on disk

Diagram 2 — this file has no config import and no open(). The two keys in the top box are read in sources/evaluators/hybrid_verifier/evaluator.py (L213 for the pairwise mode, L216 for the reward mode) and passed in as the mode argument.

Diagram 3 — the decision rules: drop test, stage ladder, Newton stop test

Diagram 3 — three real loops and tests. The ladder is walked earliest stage first (aggregation.py::STAGES L47), so a script-stage failure decides the pair before any result-stage score is read. The strict mode skips the per-stage counting and returns at the first claim with different scores (L145–L159).
