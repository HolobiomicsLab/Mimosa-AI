Tools, MCP and LLM providers

sources/core/tools_manager.py scans configured IP/port ranges for MCP servers and turns their tool lists into prompt text and client code. sources/core/llm_provider.py wraps one LLM call behind litellm with a disk cache, an infinite retry loop, and per-call persistence. The literature client sources/utils/perspicacite_client.py is documented on area_utils.html.

Diagram 1 - MCP discovery

Diagram 1 - seven boxes. Chain: config.py::Config.discovery_addresses to sources/core/tools_manager.py::ToolManager.discover_network_mcp_servers to sources/core/tools_manager.py::ToolManager.discover_mcp_at_address to sources/core/factory.py::Factory.load_tools_code. Dashed boxes are external services; dashed arrows are traffic to and from them.

These two files decide which tools and which model a generated workflow gets: a closed port or a bad model id stops the run before any science happens.

Amber: the ToolHive path is disabled at the call site - sources/core/tools_manager.py::ToolManager.discover_mcp_servers sets mcps_thv = [], so only the network scan runs while discover_toolhive_servers stays unused.

Red: sources/core/tools_manager.py::ToolManager.discover_mcp_at_address documents "Per-port timeout in seconds when probing. Defaults to 2.0", but the code hardcodes timeout=3.0 in the Client(...) call and never passes the timeout argument.

Diagram 2 - eight boxes. The chain is sources/core/llm_provider.py::LLMProvider.__call__ to litellm.completion; the cache and pricing paths hang off the memory folder. The runner's smolagent agents use smolagents LiteLLMModel directly and do not pass through LLMProvider - see mod_core_runner.html.

Finds MCP servers on configured ports, stores each server with its tools, and writes client code plus tool descriptions for the workflow prompt.

Facts from the code: discover_network_mcp_servers passes addr.port_min and addr.port_max, so the range comes from config, not from the function defaults (defaults are 5000 to 5250; config.py default is 5000 to 5200). Per-port probing uses a hardcoded timeout=3.0 and a 3.0 s client timeout; a failed port is swallowed by a bare except Exception: continue. Network-discovered entries store the raw smolagents tool objects in MCP.tools (typed list[Tool] in the docstring); the local Tool wrapper is only built by the ToolHive JSON path _get_tools_with_descriptions. get_client_code raises ValueError for stdio and for entries with no URL.

sources/core/llm_provider.py

Sends one prompt to an LLM through litellm, returns text, and persists the call JSON for cost accounting.

643 lines · classes: LLMConfig, LLMProvider · function: extract_model_pattern · writes: <memory_path>/<agent_name>.json · covered by tests/llm_provider_test.py

what __call__ wraps
LLMProvider.__call__(prompt, timeout=180, use_cache=True) -> str
  1. _find_cache_match(prompt)          - exact match on (sys_msg, prompt); returns cached text
  2. litellm.completion(...)            - inside `while True` with exponential backoff and jitter
  3. save_call(json_res)                - when both memory_path and agent_name are set
LLMProvider._apply_cache_control(messages)  - ephemeral cache_control on the system block
LLMProvider._is_retryable_error(error)      - matches overload, rate_limit, timeout, 429, 5xx, context
LLMProvider._calculate_backoff_wait(attempt, max_wait=500) - 2**attempt plus jitter, capped at 500 s
LLMProvider._is_temperature_error(error)    - retries once with temperature = 1.0
LLMProvider._is_quantization_routing_error(error) - drops the OpenRouter quantization filter and retries
LLMConfig.from_dict(config)                 - dict to config, missing keys take defaults

Notable behaviours. Claude models get no temperature and no reasoning_effort parameter (_is_claude_model). Context-window errors shrink the user prompt to 0.5 ** n of its length for at most 3 rounds, then fall back to backoff retries. A null content becomes the string <LLM response error>. The persisted JSON adds response, message, temperature, reasoning_effort and model as provider/model so the pricing matcher can find it.

Cache detail: with use_flat_cache=False, _find_cache_match globs every subfolder of the memory parent folder and returns the first exact match, so a response written by another run with the same system message and prompt is returned.

Literature client: sources/utils/perspicacite_client.py (394 lines) queries PERSPICACITE_API_URL (default http://localhost:5468) at /api/chat, caches answers under sources/memory/perspicacite_requests/<sha256>.json, and returns None when the service is down. Full card on area_utils.html; its callers are sources/core/planner.py::Planner.perspicacite_grounding and sources/core/orchestrator.py::WorkflowOrchestrator._ground_with_perspicacite.
