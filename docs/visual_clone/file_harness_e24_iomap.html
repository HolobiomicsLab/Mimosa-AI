e24_iomap.py

This file is E24 Phase 0: one LLM call per group maps the workspace I/O — the entry script, the train and test files, the prediction output and the metric kind implied by the goal wording. The same file then evaluates four deterministic gates on the frozen files (entry, data, relative paths, consumable outputs) and declares which groups admit the verifier-owned holdout. Three commands: map L18, gates L19 and pilot-verdict L367.

Diagram 1 — the job: one mapping call per group, then four deterministic gates

Diagram 1 — the mapping call sees only the goal, the union inventory and the previews L157–L161; no gold, SR or VER enters the prompt. The gates then re-read the frozen files themselves L226–L270, so they do not trust the model.

Diagram 2 — data flow: arena, goals and snapshot files in; three result files out

Diagram 2 — config fields read: none. Constants read: GOAL_CHARS 2400 L76, PREVIEW_CAP 16 KiB L75, PILOT_GROUPS L327. The stream of the store: the map keeps what the model returned, the gates keep only booleans and hit counts L291–L300.

Diagram 3 — logic: the gate chain, the C2 rule and the pilot threshold

Diagram 3 — each gate needs half the generations (G3 half the generations that resolved an entry script L245), the C2 rule adds the metric test L273, and pilot_verdict needs 3 of the 5 declared pilot groups L343. Both commands print the verdict and write it.
