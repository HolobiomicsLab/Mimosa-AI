evaluator.py

WorkflowEvaluator is the facade the evolution engine builds once per campaign: it constructs the generic, scenario and verifier evaluators, then routes every evaluate() call by evaluator_type. The verifier channel is chosen once from config.verifier_kind: hybrid (default), legacy (deprecated), gold (oracle) or policy_bt, each behind a lazy import, and any unknown value falls back to hybrid. The module also re-exports the public evaluator names for downstream importers.

Main diagram - build three evaluators, route by type

Diagram 1 - the facade has two jobs: build the evaluator set in __init__ (sources/evaluators/evaluator.py:55-131) and dispatch one call in evaluate() (:134-195). Four verifier branches exist, one per verifier_kind value; the ORACLE branch reads the benchmark gold oracle - leaks gold. Solid arrows are calls, dashed arrows are stored-instance reads; every box also names its real line numbers.

The default run path is the verifier route: the evolution engine always passes evaluator_type="verifier" (sources/core/evolution_engine.py:1218-1234), and runs the call in asyncio.to_thread only when judge.verifier_kind == "gold"; the generic and scenario routes exist for other callers.

Data flow - what goes in, what comes out

Diagram 2 - inputs, outputs and the files the children write. evaluate() returns a small routing dict; the scores themselves land in the run folder through the child evaluators.

Control logic - the type dispatch and the scenario fallback

Diagram 3 - the dispatch tree of evaluate(): type check (sources/evaluators/evaluator.py:161-166), scenario gate and fallback (:169-182), verifier route (:184-186), generic default (:188-190). The verifier route has no idea which channel it calls; __init__ already fixed that.

Amber: the fallback at lines 181-182 and the generic default at line 189 discard their child's return value. GenericEvaluator.evaluate() returns None and writes the scores to state_result.json, so the dict this facade returns for those two routes carries evaluation_type and uuid only, with no score inside.
