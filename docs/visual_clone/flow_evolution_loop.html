Evolution loop

One round of EvolutionEngine.evolve_generation turns generation N into generation N+1. The verifier scores the workspace, writes a textual gradient, the archive accepts or rejects the offspring, and VariationEngine builds the prompt for the next genotype. This page follows that cycle and the QD filter that decides which genotypes stay.

The loop: generation N becomes N+1

Diagram 1 - the closed loop, 11 boxes. At the score step WorkflowEvaluator picks the verifier by config.verifier_kind (sources/evaluators/evaluator.py:88-110): "hybrid" (default), "legacy" (deprecated) or "gold", an ORACLE mode oracle - leaks gold. Only gold runs in asyncio.to_thread (sources/core/evolution_engine.py:921-932). The gradient text is the only feedback the mutator receives: it reads WorkflowInfo.abstracted_textual_gradient and never touches the verifier's score vectors. With gold, that text is the benchmark grader's VER/SR feedback.

The reward travelling from the verifier to the archive is a scalar; the per-claim scores behind it stay in the verifier, and the mutation prompt sees the whole gradient text (the 2 048-character cut is gone from the working tree).

After the last round, _select_best_run picks the capsule run and skips fallback rewards (file_core_evolution_engine.html, Diagram 4). Honest runs also skip oracle generations when they build the parent pool (WorkflowSelector.discover_workflows, see mod_core_selection.html).

Archive and QD selection filter

Diagram 2 - the QD filter inside SelectionPressure.validate_survivor. A rejected offspring returns admit_rejected = True and the archive keeps its previous members. novelty_comparison = "previous_n" swaps the archive k-NN peers for the last N genotypes.

is the gradient fed whole or summarized?

Stored whole, fed whole on both paths.

  • The verifier stores the full text under abstracted_textual_gradient in the run's state_result.json (sources/evaluators/hybrid_verifier/evaluator.py:631) and writes it to sources/workflows/<run>/<uuid>/textual_gradient.txt (HybridVerifierEvaluator._write_artifacts).
  • WorkflowInfo.abstracted_textual_gradient (sources/core/workflow_info.py:241) reads the state key first, the sidecar file second.
  • Mutation path: VariationEngine.mutation_prompt replaces _ with a space and sends the rest whole (sources/core/variation_engine.py:402-407). The [:2048] cut at L407 was removed in commit ca72107. No other summary is computed.
  • Crossover path: each parent's gradient goes in whole, with no character cap; only the fallback (stderr tail) is cut to the last 1 024 characters (sources/core/variation_engine.py:486-489).
  • Measured size: the gradient quoted below is 4 428 characters. At 4020790 the 2 048 cut kept about 46 % of it; the working tree sends all of it (my computation).

where the raw scores stay inside the verifier
  • Per-claim score vectors live in the per-task registry hybrid_registry_<16-hex>.json (TaskRegistry.load, sources/evaluators/hybrid_verifier/registry.py:82), written by TaskRegistry.record_generation and read back by TaskRegistry.previous_generations on the next round.
  • The LLM-written policy-scorer scripts are stored in that same registry (TaskRegistry.set_scorer, registry.py:247), and the scorer runs as a subprocess with a 60 s timeout (hybrid_verifier_scorer_timeout_s).
  • The engine reads from the verifier: the scalar overall_score (WorkflowInfo.overall_score, workflow_info.py:156), the flag reward_is_fallback (workflow_info.py:200), the gradient text, skipped_reason, and for the capsule pick reward_fallback, reward_source, n_pairs, n_wins (_run_reward_is_fallback). No module in sources/core/ imports sources/evaluators/hybrid_verifier/; the engine reaches it only through sources/evaluators/evaluator.py::WorkflowEvaluator.evaluate.
  • Inside the verifier, sources/evaluators/hybrid_verifier/aggregation.py::win_rate_reward turns the score vectors into the reward (temporal_winner decides each pair at the earliest differing stage).
  • Leak to state clearly: the gradient text itself does contain claim scores and evidence lines (for example score: 1.000). The mutator sees those numbers inside the gradient, but never the scorer code or the score vectors.
