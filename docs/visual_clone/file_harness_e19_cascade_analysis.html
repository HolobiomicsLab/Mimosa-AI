e19_cascade_analysis.py

Offline follow-up that lets E19-tied pairs fall through to a second channel (E15, uniform or reward) and ranks the resulting cascades. It makes zero LLM calls and appends a cascade_ensemble_analysis section to the E19 result files. Run with uv run python experiments_verifiers/harness/e19_cascade_analysis.py.

Diagram 1 — what the file does

Diagram 1 — 8 boxes in execution order; main (L225) drives all of them. The pair decisions of the primary channel are recomputed here rather than read from the E19 JSON, so the cascade and the E19 ranking are built from the same score ledgers.

Diagram 2 — data in and out

Diagram 2 — 7 boxes. The JSON is re-read at L361 before the merge, so the original readouts stay in the file and only the cascade_ensemble_analysis key is set. On the markdown side the section is idempotent: any text from SECTION_TITLE down is cut first (L422–423).

Diagram 3 — cascade rule, replay pick and verdict

Diagram 3 — 9 boxes, one per real condition. The cascade wrapper is the 5-line function at L142–148; the fall-through counter at L172–184; the tournament pick key at L205–212; the correlation gate at L290–294; the three-way verdict at L328–338; the markdown cut at L422–423.

Why it matters: the cascade answers the operator question "does a tie-break channel add signal?", and the paired diffs and the verdict print it as an answer, not as a table of raw scores.

Amber: the M2 table in the markdown mixes values read from this run (E15, best cascades) with hardcoded reference numbers for the other rankers (E19 8, E18 8, reward 8, uniform 9, oracle 12) at L400–403.
