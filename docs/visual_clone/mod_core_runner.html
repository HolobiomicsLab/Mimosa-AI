Sandboxed execution: runner and factories

These five files turn a goal into a Python program and then run it. The factories splice the LLM-written workflow with two injected templates; workflow_runner.py writes the result to a temp script and starts a host subprocess. The single-agent path replaces the LangGraph workflow with one CodeAgent script.

Synthesis to workspace

Diagram 1 - arrow labels name the symbol that produces the flow. Entry point: sources/core/evolution_engine.py:495 calls orchestrator.orchestrate_workflow(); the tuple (output, uuid, genotype, executed) returns to the evolution loop.

The AST allow-list is not in workflow_runner.py: it lives inside the SmolAgents CodeAgent that the injected SmolAgentFactory builds, so it applies to agent-written code inside the run, not to the assembled script itself.

The sandbox boundary

Diagram 2 - two lists in one diagram. Left: what the injected agents may import. Right and bottom: what the executor denies and what the runner enforces.

Docs mismatch: docs/concepts/architecture.md:74 says the runner imposes "per-run limits on time, memory, and CPU", but RuntimeConfig.max_memory_mb and max_cpu_percent (sources/core/workflow_runner.py:81-82) are stored and never read; only timeout is enforced.
