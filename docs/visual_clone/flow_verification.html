Hybrid verification flow

The hybrid verifier grades one workflow workspace per generation. It spends one LLM call on 8–12 stage-tagged claims, then one LLM call per claim to write a deterministic Python scorer, and runs each scorer as a host subprocess. The reward is a pairwise win-rate over the task's previous generations, decided at the earliest ladder stage where the two differ.

The temporal ladder and the pairwise decision

Diagram 1 - the three rungs of the ladder and the comparison rail below them. Winner logic: sources/evaluators/hybrid_verifier/aggregation.py::temporal_winner. The rail compares the current generation against every previous generation of the same task. Figure tasks put a visual rung before script (aggregation.py::FIGURE_STAGES, hybrid_verifier_visual_rung, default True).

A claim passes its rung at score >= 0.5 (PASS_THRESHOLD), so a script-stage failure dominates a later result-stage advantage. Claims with no score variance across workspaces are dropped (claim_stats, MIN_OBS_FOR_VARIANCE = 2) and may be replaced by refinement claims.

Call sequence for one generation

Diagram 2 - call order for one generation. Steps 3, 5 and 7 are one LLM call each (step 7 runs once per claim); step 8 runs the scorer subprocess with cwd = workspace, and step 11 returns the scores plus the gradient. In gold mode step 1 comes from GoldFeedbackEvaluator.evaluate, not from the facade (next panel).

Where the verifier kind is chosen - and the gold branch

Diagram 3 - sources/evaluators/evaluator.py::WorkflowEvaluator.__init__ chooses the channel once. Gold does not replace the ladder: sources/evaluators/gold_feedback/evaluator.py::GoldFeedbackEvaluator.evaluate runs the full hybrid first (built with gold_hybrid_config), then grades a private copy of the workspace, then swaps only abstracted_textual_gradient and textual_gradient.txt. oracle - leaks gold

Amber: gold feeds the benchmark verdict against the gold reference back into evolution; leak.py::LEAK_WARNING says its scores must never be reported. With no task row (any run without --science_agent_bench) or a censored grade, the hybrid gradient stays (STATUS_NO_TASK, STATUS_CENSORED).

Amber note: the scorer is not sandboxed. It runs as a subprocess of the host interpreter - RuntimeConfig(python_executable=sys.executable, use_pty=False) with the workspace as execution directory (sources/evaluators/hybrid_verifier/evaluator.py::HybridVerifierEvaluator._execute_scorer_script). AGENTS.md states the same exception under Security considerations; only static screening, a read-only contract and the 60 s timeout hold the line.

Red note: AGENTS.md says generated workflow code runs through the SmolAgents sandbox "in sources/core/workflow_runner.py", but LocalPythonExecutor appears nowhere in sources/ (grep, 2026-09-28). workflow_runner.py runs a generated script as a subprocess (WorkflowRunner.execute).

The reward is relative: it compares the current workspace only against previous generations of the same task goal, and the registry file is keyed by sha256(goal + registry_version).

pairwise modes and reward maths
PAIRWISE_MODES      temporal (default), temporal_strict, mean_diff, sign_sum, escalation
