selection.py

This file holds SelectionPressure, the part of the evolution loop that decides which generated workflow survives, plus the four selection strategies (greedy, tournament, novelty, quality-diversity) and the in-memory QD archive. It runs twice per generation: once after scoring, when EvolutionEngine.validate_survivor is called (evolution_engine.py:563), and once before mutation, when a parent is drawn (workflow_selection.py:279). It reads run objects and config fields, stores state in memory, and writes nothing to disk.

Diagram 1 — what the file does, left to right

Diagram 1 — lane 1 flows left to right (dispatch and admission), lane 2 covers the QD numbers, lane 3 hands the next generation back. Every arrow is a real call or a real read of selection.py: validate_survivor routes greedy and tournament to _validate_greedy/_validate_tournament (L177–180) and both open-ended values to _validate_open_ended (L181–182). Greedy and tournament never call _try_admit; only the open-ended path admits to _archive (L439). _archive is only filled in the open-ended modes, so the parent lane is archive-driven only there (L219–235).

Diagram 2 — what goes in, what comes out

Diagram 2 — dashed boxes are reads or writes; the blue boxes are values this file returns or stores. selection.py opens no file: the three dashed artefacts on the right (qd_archive.jsonl, archive_pca.png, log lines) are written by EvolutionEngine from the returned verdict and the public archive property (L289). The config dict passed to __init__ is stored as self.config (L119) and never read again in this file — the ten knobs are read by the caller instead (evolution_engine.py:97–106).

Diagram 3 — control flow: three strategy branches, one admission loop

Diagram 3 — the real conditions, thresholds and defaults. novelty and qd share every box in the right column: validate_survivor routes both to _validate_open_ended (L181) and select_parent treats them as one case (L218). The dashed edge is the loop: one admission per scored generation, repeated by the evolution engine. Two random draws make the result non-deterministic in tournament mode (L362, L366) and in the crossover coin flip (L267).

Docstring drift, my reading only: __init__ documents min_improvement_threshold as "Minimum relative improvement for greedy mode (5% default)" (L101), while the signature default is 0.01 (L86) and config.py:142 sets 0.01. The 5 % figure appears nowhere in the code path. Not verified by a run.

Amber, unused and test-only paths: the config argument is stored as self.config (L119) and never read in this file. The pre-computed branch of _extract_behaviour_descriptor (L484) reads run.behaviour_descriptor, but IndividualRun (schema.py:43–72) has no such field, so at runtime the embedding path at L488 always runs; the injected path is used by tests/selection_test.py stubs (L49–65).

Signature defaults versus wired defaults differ, so the Config values are what count in production: population_size 25 in the signature (L88) against 16 in config.py:143, novelty_k_neighbours 10 (L89) against 16 (config.py:144), previous_n 5 (L94) against novelty_previous_n 16 (config.py:137). evolution_engine.py:97–106 always passes explicit values, and config_default.json repeats the Config numbers.
