variation_engine.py

This file writes the prompts that steer each workflow mutation and crossover, and it keeps the search statistics that go into those prompts. It runs inside the evolution loop, called by EvolutionEngine before each new generation. It reads scores and diagnoses; it never runs a workflow.

Diagram 1 — the job: history in, prompt out

Diagram 1 - 10 boxes. Solid arrows are calls; dashed arrows carry a value. The directive LLM is the only model call in the file: mutation_prompt calls it (line 428), it returns text, and the text is embedded inside <directive> tags (line 444). The gradient path is on Diagram 1b.

Diagram 1b — where the textual gradient goes now

Diagram 1b - 10 boxes. The 2048-character cut on the gradient is gone (variation_engine.py:407, git diff 336fe19): in mutation the full gradient reaches the directive LLM only, in crossover it reaches the mutator directly. Two cuts remain: each agent answer at 2048 characters (line 274) and the crossover stderr fallback at the last 1024 (line 489).

A mutation child never sees the raw gradient: mutation_prompt embeds only the directive text, so the gradient length changes the directive LLM input, not the mutator input.

Diagram 2 — data flow: fields and scores in, prompt and telemetry out

Diagram 2 - the module reads config fields plus three WorkflowInfo properties, keeps its history in memory, and returns strings and one dict. Persisting that dict is the engine's job, not this file's.

Diagram 3 — logic: the loop, the stop test and the branch

Diagram 3 - three independent mini trees, each inside one method. The dashed return arrow at the left is the loop: the streak counter walks backwards until an entry improves. Column headings are plain text, not boxes.
