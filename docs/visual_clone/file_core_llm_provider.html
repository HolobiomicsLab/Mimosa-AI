llm_provider.py

One callable that every LLM user in the framework goes through: LLMProvider(prompt) returns text from litellm behind a disk cache, a retry loop with backoff, and OpenRouter provider pinning. LLMConfig in the same file holds the request settings and resolves the API key from the environment. It runs on every generation, judge, planner and memo call; the module page covers it next to the MCP tool manager.

Diagram 1 — what this file does: prompt in, cached retried completion out

Diagram 1 — 11 boxes. Order of work inside __call__: cache lookup (440-443), message assembly (445-449), then an unbounded while True loop whose body builds completion_params, calls litellm.completion, and on failure classifies the error (497-569). extract_model_pattern is a leaf helper: this file never calls it, importers do.

Diagram 2 — data flow: keys, cache files, returned text

Diagram 2 — 6 boxes. The provider never reads config.py: callers build an LLMConfig from their own config field (sources/core/variation_engine.py:50-51, sources/transparency/astra_exporter.py:152-153). Files written: one JSON call record per agent name, and only when both memory_path and agent_name are set (line 619).

Diagram 3 — control logic: the retry loop and its four repairs

Diagram 3 — 12 boxes. The four repairs: set temperature = 1.0 (516), set config.openrouter_quantizations = None (529, which persists for later calls), shrink the user prompt by 0.5**n up to three times (537-551), and exponential backoff 2**attempt plus jitter capped at 500 s (403-418). The ceiling is self.max_retries = 100 (196).
