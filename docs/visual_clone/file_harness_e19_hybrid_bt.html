e19_hybrid_bt.py

The E19 driver: it extracts 3–7 key claims per task group, writes one deterministic scoring script per claim, executes that script on every candidate workspace, and drops claims that vary nowhere. It has seven subcommands and a hard cost cap, and it owns the four E19 ledgers. Run with uv run python experiments_verifiers/harness/e19_hybrid_bt.py status|pilot|extract|score|run|det|verify.

Why it matters: the same script scores every workspace of a group, so a score difference comes from the artifact, not from a new judge draw.

Amber: _load_env (L158–165) copies variables out of the key files into os.environ, while execute_scorer (L612–613) passes a stripped environment to the child process, so the scorer script never sees the key.

Red mismatch: on disk experiments_verifiers/results/_e19_pilot_2026-09-23.json has all_pass: false and gate_2_surviving_all: false (drugex_vis kept 1 claim), while the same file also carries keys this file never writes — gate_verdict_strict, failed_criteria, passed_criteria, operator_decision_2026_09_24, history. The record was extended after the run, so all_pass alone does not describe the decision that was taken. e19_bt_eval.py reads that extended record at L556–558.
