e5_run.py

This 524-line script is the E5 experiment: it fits four rungs of a claim-importance ladder (source means, kind-by-importance groups, lexical features, name embeddings) under task-level leave-one-task-out and writes one results JSON. It runs by hand, uv run python experiments_verifiers/harness/e5_run.py (docstring L3), and uses e5_common.py for loading, provenance and metrics. Every number it stores is labelled "my computation" (L495).

Diagram 1 — what the file does: load, classify provenance, build four feature sets, LOTO-fit each, write the record

Diagram 1 — 10 boxes. main is the only caller of the rung code; loto_eval is the shared engine, and the four feature builders are passed into it as feats_fn (L399–L424). The classifier is optional: make_f_src(..., predicted_fill=True) (L398) is the only rung that needs it.

Diagram 2 — four frozen reads, one write, one return. OUT_MD is built at L29 but never used: the markdown file comes from e5_md.py, which this script does not call.

Diagram 3 — the leave-one-task-out loop and its stop tests

Diagram 3 — one loop body, three guards. permutation_test calls loto_eval once per shift (L307), which is why the 200 permutations dominate the runtime the payload reports at L516.

Red: OUT_MD is defined at L29 (EV / "results" / f"E5_learned_importance_{TODAY}.md") and never read again; the docstring at L4 also promises that this script writes the .md, but the markdown is produced by e5_md.py.

Amber: the split policy is positional, not random, inside loto_eval — the inner folds are j % 4 over the sorted task list (L242–L243, L269), so the same task always lands in the same inner fold.
