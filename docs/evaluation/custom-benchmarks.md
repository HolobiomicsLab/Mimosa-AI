# Custom benchmarks

Run Mimosa-AI on your own CSV of tasks. Useful for internal benchmarks,
private datasets, or domain-specific reproductions.

!!! info "Two systems again"
    This page covers batch execution and per-task aggregation. The
    **per-generation pressure signal** (and the textual gradient that
    drives evolution) still comes from the in-loop verifier described
    in [Evaluation pipeline](../concepts/evaluation-pipeline.md). A
    custom benchmark either layers a scenario rubric on top (see below)
    or relies on the verifier alone for scoring.

## Minimum CSV schema

`--papers` mode reads these CSV columns by name (`sources/benchmark_evaluation/csv_mode.py:1450`):

| Column | Required | Description |
| ------ | -------- | ----------- |
| `Prompt` | no | Task text used as the goal. The default path uses a fallback prompt when it is empty. |
| `Title` | no | Read by the default path. |
| `URLS` | no | Read by the default path. |

Other columns are ignored in this mode. `task`, `prompt`, `expected_output` and `instance_id` are not read by the default path. `datasets/ScienceAgentBench.csv` has its own schema (`instance_id`, `task_inst`, `output_fname`, `domain_knowledge`, ...) and is used only by `--science_agent_bench`.

## Running it

```bash
uv run main.py --papers datasets/my_benchmark.csv \
              --csv_runs_limit 20 \
              --config my_config.json
```

With iterative learning:

```bash
uv run main.py --papers datasets/my_benchmark.csv \
              --csv_runs_limit 20 \
              --learn \
              --config my_config.json
```

## What you'll get

Each row produces:

- A capsule in `runs_capsule/<capsule_name>/`. The name is generated by an LLM from the goal plus a task token.
- Run notes in `run_notes/<capsule_name>.json` (`sources/benchmark_evaluation/csv_mode.py:553`).
- Workspace snapshots and lineage records under `sources/workflows/`.

Only ScienceAgentBench rows also get an `evaluation_results.json` in the capsule (`csv_mode.py:788`). It holds `VER`, `SR`, `CBS`, `cost_usd` and a summary. It has no per-claim scores.

A summary prints at the end of the run. The VER/SR/CBS lines appear only when ScienceAgentBench rows ran (`csv_mode.py:1738`).

## Concurrency

`--papers` always runs one task at a time. `papers_mode` does not pass `max_concurrent_eval_tasks` (`main.py:292-298`).

`max_concurrent_eval_tasks` applies to `--science_agent_bench` and the evaluation CLI (`main.py:300-305`, `sources/cli/evaluation_cli.py:1088`):

```json
{
  "max_concurrent_eval_tasks": 4
}
```

`task_start_delay` staggers launches so concurrent runs don't all hit the same MCP discovery and LLM warm-up spike. It is a constructor argument of `CsvEvaluationMode` (`csv_mode.py:184`) with default 30.0. It is not a config key, so setting it in config JSON has no effect.

## Scenario-based evaluation

If you have a hard ground-truth assertion list per task instead of free-form expected outputs, write a **scenario file** (JSON) and run:

```bash
uv run main.py --scenario <scenario-file>.json
```

The scenario file needs `id`, `goal` and `assertions` fields (`sources/benchmark_evaluation/scenario_loader.py`). `--scenario` loads the file, uses its `goal` as the task (`main.py:352-354`), and scores each run against the assertions.

The scenario scorer is an LLM judge, not a string matcher (`sources/evaluators/scenario/scenario.py:19`, `:370-377`).

`main.py` loads through `ScenarioLoader()` with its default directory `datasets/ScienceAgentBench/scoring_rubrics` (`scenario_loader.py:19`), while the judge's own default is `datasets/scenarios` (`scenario.py:30`). Keep the scenario file where the loader looks.

See [`sources/benchmark_evaluation/scenario_loader.py`](https://github.com/HolobiomicsLab/Mimosa-AI/blob/main/sources/benchmark_evaluation/scenario_loader.py) for the loader and [`sources/evaluators/scenario/scenario.py`](https://github.com/HolobiomicsLab/Mimosa-AI/blob/main/sources/evaluators/scenario/scenario.py) for the scoring logic.

## Reset between runs

```bash
./cleanup.sh
```

Deletes the top-level generation folders of `sources/workflows/` and
empties `tmp/`. Pass a subfolder name (`./cleanup.sh run_1`) to empty
one child folder of `sources/workflows/` instead; it asks first unless `-y` is given. Do this before any benchmark you want
to publish — without it, cached workflows from prior runs can leak
through similarity-based parent selection.
